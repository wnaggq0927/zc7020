5.3产品介绍
OTDR的英文全称是Optical Time Domain Reflectometer，中文意思为光时域反射仪。OTDR Module是利用光线在光纤中传输时的瑞利散射和菲涅尔反射所产生的背向散射而制成的精密的光电一体化模块，它被广泛应用于光缆线路的维护、施工之中，可进行光纤长度、光纤的传输衰减、接头衰减和故障定位等的测量。OTDR Module是本公司研制的高性能OTDR模块系列产品，主要集成了光接口，数据处理等核心部件，对外提供以太网接口和并行接口，可以轻松进行二次开发；并提供串口，可以进行状态查询等简单控制以及模块参数的修改。本产品具有小巧、经济、方便、高效的特点；可用于查找整个光纤链路的实际故障状况；可广泛应用于光纤铺设、日常维护、野外施工以及故障分析。 
本模块与上位机（PC机或嵌入式系统）通过以太网相连接即可完成工作，即：上位机对OTDR模块下达测量命令，并接收模块的返回结果即可完成全部工作。 
本模块支持用户二次开发应用，帮助用户以最快的速度开发出自己的专业OTDR仪表或光纤在线监测系统。用户只需要做部分人机界面的开发，就能完成OTDR的研发工作，快速抢占市场,也可以方便的嵌入到其他光通讯设备或者系统中，提供OTDR功能。

OTDR Module 2.0技术文档
概述
OTDR Module是本公司开发的高性能OTDR 模块系列产品。对外提供以太网接口，用户可以轻松进行二次开发。
本文档将分两部分来介绍该OTDR Module的开发，分别是硬件接口和软件接口。在硬件接口部分中，详细介绍OTDR Module对外的接口信号，以及对外部电源的要求。在软件接口部分中，详细介绍所用的TCP通信协议，全部的开发命令，以及一般的开发流程。
OTDR Module硬件接口
OTDR Module对外提供以太网接口，上位机与模块之间使用最少的连线，即可进行二次开发。具体电气接口说明如6.2设备接口说明。
以太网接口通信协议
OTDR Module是提供以太网接口的OTDR模块，上位机与模块使用TCP网络协议进行通信，也可定制成使用UDP协议。这种方式将使用最少的连线，用户只需配备上位机CPU，及相应的电源电路和存储电路即可进行二次开发。这里假设用户熟悉TCP/IP网络协议。
IP地址
OTDR模块的IP地址默认为192.168.1.249，通信端口号为5000。该IP地址可以通过下面介绍的通信协议命令来修改。
网络字节序
对于多字节数据，由于处理器的差异，有可能会引起字节序的问题。CPU一般分大端格式和小端格式两种，它们的主要区别在于多字节数据在内存中是高字节数据存储在低地址，还是高字节数据存储在高地址。比如数据0x1234，如果它在内存中的地址为p，对于大端器件，高字节数据存储在低地址，则地址p内存储的字节数据将是0x12，地址p+1内存储的字节数据将是0x34，很直观；对于小端器件则正好相反，低字节数据存储在低地址，地址p内存储的字节数据将是0x34，地址p+1内存储的字节数据将是0x12，符合人的思维。
网络字节序规定了在网络传输中，多字节数据先传输高字节，遵循“所见即所得”的原则。对于大端器件，由于在内存中先存储的是高字节数据，已经符合网络字节序，所以可以直接使用send函数发送一块内存数据，即使数据中包含了多字节数据也不会引起问题。而在接收数据的时候，如果数据满足网络字节序，则可以直接接收不用做任何处理，即使数据中包含了多字节数据也不会引起问题。对于小端器件就不同了，如果数据中包含了多字节数据，则在发送前必须使用htons宏（函数）或者htonl宏（函数）将数据转换成网络字节序，在接收后必须使用ntohs宏（函数）或者ntohl宏（函数）将数据转换成本地字节序。
考虑到小端器件使用得比较多，所以在这里规定，不使用网络字节序，所有数据直接使用send函数发送到网络！如果用户的CPU是小端器件，则可以直接处理所有数据，不用作任何改动； 而如果用户的CPU是大端器件，则需要编写函数或者宏来将本地字节序转换成协议字节序，同时编写函数或宏来将协议字节序转换成本地字节序，浮点数据还要作更多的处理。整数和浮点数从本机字节序转换为网络字节序的转换函数，详见第四章《以太网接口的典型开发流程》。
下面举例说明多字节数据及浮点数在小端器件内的处理。对于32位整型数据i32 = 0x12345678，它在内存中的存储依次是0x78, 0x56, 0x34, 0x12，所以发送的次序还是0x78, 0x56, 0x34, 0x12，对端也按这个次序接收到数据；对于32位浮点数f32 = 1.4685，对应的整型存储数据是0x3FBBF7CF，在内存中的存储依次是0xCF, 0xF7, 0xBB, 0x3F，所以发送的次序还是0xCF, 0xF7, 0xBB, 0x3F，对端也按这个次序接收，如果对端CPU是小端格式，则可以直接解析，否则必须把顺序转换过来才可以解析。
响应回帧
对所有从上位机发送的命令，模块在接收到后都有响应回帧：如果命令参数错误，则返回参数错误码；如果命令正常，同时该命令又需要返回数据，如果模块可以立即返回，则直接返回数据，如果需要过一段时间才能返回数据或者命令不需要返回数据的，则模块返回成功处理命令的状态码。状态码在下面的“状态码”部分定义。

下面是各字段说明
起始帧（STPKSTR）：长度16字节，识别一个帧的起始，类型为String，并以’\0’结束，在此设置为GLinkOtdr-3800M；
总帧长（PKLEN）：长度4字节，类型为Uint32，表示整个数据包的长度，其值为16+10*4+n；
版本号（REV）：长度4字节，类型为Uint32，表示当前使用的协议版本号，如0x00000001 ，表示协议为版本v0.001； 在本协议中不处理；
帧类型（PKTYP）：长度4字节，类型为Uint32，如：0x00000000 表示从上位机发送的命令帧，0x00000001 表示从模块发送的命令响应帧；在本协议中不处理；
源地址（SRC）：长度4字节，类型为Uint32，发送方填写本身IP 地址，16 进制值，表示数据包的来源；在本协议中不处理，可以设定为0；
目的地址（DST）：长度4字节，类型为Uint32，发送方填写数据包发往的目的IP 地址，16 进制值；在本协议中不处理，设定为0；
流水号（PKID）：长度4字节，类型为Uint32，由发送方填写，每次顺序递增，接收方直接引用返回，不修改，用于唯一标识一个数据包；在本协议（TCP）中不处理，可为任意值；如果使用UDP协议，则该域可以用来指示分包的序号。
命令码（CMDCODE）：长度4字节，类型为Uint32，由发送方填写，用于表示一项操作命令。本协议中规定，从上位机发送的命令，其命令码范围为0x10000000~0x7fffffff，从OTDR模块发送的命令，其命令码范围为0x90000000~0xffffffff；
数据长度（DATLEN）：长度4字节，类型为Uint32，表示随后数据区的长度，其值为n；
数据区（DATA）：长度n字节，与具体命令相关的数据，其数据格式在具体的项目中另行约定；
保留字节（RSVD1~RSVD2）：长度4字节，类型为Uint32，为以后扩展使用，未用填充0xffffeeee；

刷新周期
	设定已经使能数据刷新的平均模式的刷新周期，以及实时模式的测量时间，单位为ms。当处于平均模式并且禁止数据刷新时，该值无效。刷新周期必须大于1000ms，不可超过5s，并且必须是200ms的整数倍。如果小于1000，则OTDR模块自动改为1000；如果超过5s，则OTDR模块自动改为5s；如果不是200的整数倍，则OTDR模块自动向上改为200的整数倍，即如果设置为700，则结果是1000；如果设置为1050，则结果为1200；如果设置为5500，则结果为5000。
刷新次数的计算：如果设置了刷新周期为2000ms，测试时间为15s，则15000/2000 = 7.5，如果刷新7次，共需时14s，那么最后只剩下1s，时间短于一个刷新周期，有可能会引发实时性的错误。所以OTDR只刷新6次，最后一次上传的数据就不是刷新数据了，而是全部测试时间里获得的数据。而如果设置刷新周期为1000ms，测试时间为15s，则15000/1000 = 15，将会刷新14次，最后一次上传全部数据。
也就是：刷新次数=(int)(测试时间/刷新周期)-1
注：第一次刷新时由于要获取数据，所以其时间间隔要长于刷新周期，其后的时间间隔就等于刷新周期了。

	事件点N的插入损耗。对于光纤起点和终点，无需计算此项数值
	float
事件点N和N-1之间的光纤平均衰减系数
	事件点N与其前一事件点之间的光纤段平均衰减系数。对于光纤起始点，无需计算此项数值
	float
事件点N的累计损耗
	事件点N距被测链路起始点的链路总损耗。
	float
备注：在不同的量程下，OTDR使用不同的采样率来采集数据，如果采样率越高，则采样越密集，对应的两点距离就越近，也就是说，采样率对应着点距。假设采样率为Fs(Hz)，根据OTDR定位公式，可得点距为。所以如果事件点在曲线数组里的下标为m，则它对应的实际距离就是。
OTDR计算出来的曲线的数据是float型，其最小值为-5，最大值不超过50。在本协议的上传处理中，先将曲线值加上5，使得其全部变成非负，这样就可以用无符号整型数据来表示了，然后将加5后的数据再乘以1000，取整后按Uint16类型上传，这样可以得到3位精度，曲线更平滑细腻。上位机收到曲线数据后，应该先除以1000.0，然后再减去5，才可以恢复成与OTDR内部一样的数据。
事件点的属性一般有5个：位置、类型、插入损耗、反射损耗、累计损耗（总损耗）；光纤段的属性一般有2个：光纤段长度，光纤段平均衰减系数。在本协议中，将光纤段的属性合并到事件点的属性里一起上传，而光纤段的长度就是相邻两个事件点之间的距离，它可以用事件点的属性来表达，是个冗余量，所以并不上传光纤段长度，而只上传光纤段的平均衰减系数，并且它被放在光纤段的末端对应的事件点里上传。这样一个事件点的参数就有6个：位置、类型、插入损耗、反射损耗、累计损耗（总损耗）、与前一个事件点对应的光纤段的平均衰减系数。
在上面上传的6个事件点参数中，在有些情况下，某些参数是无法计算或者无需计算的。首先，位置和类型都是可以计算的，所以它们都会有可靠的值；其次，对于插入损耗，起始事件和结束事件是无法计算的，如果两个事件靠得太近，插入损耗也无法计算；对于反射损耗，只有反射事件才会拥有，而非反射事件是没有这个属性的；对于累计损耗，起始事件无需计算，两个靠得太近的事件点也无法计算，即使计算出来，其值也不可靠；对于光纤段的平均衰减系数，如果光纤段长度够长，则可以计算，而如果两个事件点靠得太近，导致光纤段长度太短，则无法计算平均衰减系数，即使计算出来，其值也不可信。
对于上面所有不可计算或者无需计算的属性参数，本协议一律使用保留值8192.0来表示，上位机如果发现某一属性为该保留值，可作特殊处理。
另外，上位机收到该命令后必须用“曲线接收响应命令”响应模块。

OTDR心跳检测和自动复位
考虑到OTDR模块长时间运行可能会由于外部网络复杂环境引发问题，特地加入了心跳检测和自动复位机制。
由于OTDR模块与上位机软件通过TCP协议通信，这是有连接的协议，所以OTDR模块可以检测到上位机软件是否与自己建立了连接。如果建立了连接，那OTDR模块就要求上位机软件定时发送心跳包，如果在1分钟之内都没有接收到任何心跳包，则OTDR模块认为通信异常，将会断开TCP连接，并自动复位。而如果上位机软件没有与OTDR模块建立连接，那么OTDR模块就无法收到任何心跳包数据，在1个小时之后，OTDR模块将会自动复位。
另外，如果有任何形式的数据传输错误，OTDR模块都会自动复位以消除错误。
上位机软件与OTDR模块交换心跳包数据可以通过3种方法：测试命令，echo服务器，daytime服务器。
只要上位机软件与OTDR有任何形式的数据交换，包括测试命令，停止测试命令等，OTDR模块都会认为通信正常，而不会在1min之后断开连接并复位。所以上位机软件可以定时给OTDR模块发送一些命令，比如“接收曲线响应命令”，或者非法命令（但是必须符合命令格式，这里的“非法”只是指不支持该命令码而已）等。
OTDR模块开启了端口号为5555的TCP端口，称为echo服务器。上位机软件可以通过该端口连接到echo服务器，并发送不超过64字节的数据，OTDR在收到这些数据后，会原封不动的返回给上位机。OTDR作为服务器并不会主动断开TCP连接，所以上位机软件在建立连接之后，无须再次连接，就可以进行定时通信。这一过程由于存在数据交换，OTDR会认为通信正常，而不会在1min之后断开连接并复位。
OTDR模块还开启了端口号为6666的TCP端口，称为daytime服务器。上位机软件可以通过该端口连接到daytime服务器，然后OTDR立即发送不超过16字节的字符串给上位机软件（其实该字符串是OTDR从开机到当前运行时间的毫秒数），并立即断开TCP连接，所以上位机软件在建立连接之后，不能发送数据，而应该立即接收数据（接收到的数据可以直接丢弃），并断开连接。这一过程由于存在数据交换，OTDR会认为通信正常，而将复位的时间推迟到1min之后。
上位机软件可以选择任何一种形式的心跳数据交换。如果选择方式1，其优点是不用开启额外的通信端口，软件工作量较小；但是必须处理好命令的同步逻辑处理，比如在测试过程中可以不发送心跳命令，在升级过程中也可以不发送心跳命令等。如果选择方式2和方式3，其优点是可以不改动当前的上位机软件，只要利用PC机的操作系统就可以完成心跳交换，即编写一个简单的PC端软件，它的工具就是每隔一定的时间，给OTDR的echo服务器或者daytime服务器发送数据；缺点是上位机软件没有参与到心跳交换中，不能监测到OTDR模块的状态（不能检测到OTDR模块是否因掉电等原因离线）。
以太网接口的典型开发流程
5.1概述
OTDR Module支持平均模式和实时模式两种测试模式。所谓的平均模式是由上位机发送测试命令启动测试，OTDR 模块根据用户设定的测试参数对光纤链路进行一次测试的模式。在该模式下，一个测试命令只能启动一次测试，由于测试时间比较长，上位机可以选择是否在测试过程中使能数据刷新。如果使能数据刷新，则OTDR 模块在测试时间达到了刷新周期后会计算一次曲线并上传到上位机，上位机应该注意及时接收数据并显示。如果不使能刷新，则OTDR模块会在测试结束后才计算曲线并上传。实时模式是由上位机发送测试命令启动测试，OTDR模块根据用户设定的测试参数对光纤链路进行实时监测，并在达到监测时间后计算出曲线上传，同时并不结束测试，而是继续使用原来的测试参数启动测试。在该模式下，只需一个测试命令即可对链路进行实时的监测，一般监测周期不会太长，典型值为1秒，所以并不使用数据刷新，或者说数据一直在刷新。
不能用循环启动短时平均模式测试的方法来代替实时模式，因为平均模式在测试结束后会花相当多的时间来计算光纤信息，这样势必会影响到刷新率，而实时模式并不计算光纤信息，所以其刷新率更高。
同时OTDR Module支持自动测试和手动测试模式。在自动测试时，OTDR模块会使用一定的参数测试1秒的时间来学习光纤链路，然后根据得到的数据估计出光纤长度，并自动匹配量程和脉宽，所以不需要上位机指定量程和脉宽，但如果光纤太长，如长于100km，则自动测试很可能会失败。手动测试则需要上位机同时指定量程和脉宽。当然，自动测试时上传的第一帧会比手动测试时慢。
如果平均模式使能了刷新，则OTDR模块会在达到刷新周期后计算出曲线并上传，但上传周期却往往要大于刷新周期，而且也不是一个固定值。这是因为上传周期包含了OTDR模块读取采样数据的开销，计算的开销，以及由于网络繁忙程度等引起的传输开销等。
在上传的数据里，包含平均模式的刷新数据和平均模式的最终数据，以及实时模式的刷新数据和实时模式终止测试后的最终数据。在这四种数据里，实时模式的刷新数据和平均模式的刷新数据是一样的，实时模式终止测试后的最终数据和平均模式的最终数据也一样，所以本质上只有两种数据，即刷新数据和最终数据。刷新数据只包含曲线值，并不包含测试条件信息，也不包含事件点信息，它只是起到临时显示的作用；而最终数据则包含了测试条件信息、曲线值和事件点信息，它是对光纤链路的测试的全部信息。
OTDR Module上传的刷新数据的长度是确定的，最终数据的长度可以估计。如果光纤折射率为n，采样率为Fs，光速为C，则1米对应的采样点数为Points_1m = 2n * Fs/C，所以量程为L km时采样点数为SampleNum = (Int32)( 1000 * L * Points_1m) + 1点，考虑到对齐问题，如果SampleNum为奇数，则实际上传的采样点数为UploadLen = SampleNum+1，如果为偶数，则实际上传的采样点数为UploadLen = SampleNum，最多不会超过32000。OTDR Module在量程为1km和5km时，使用的采样率是400MHz，量程为10km时，使用的采样率是200MHz，量程为30km时，使用的采样率是100MHz，量程为60km时，使用的采样率是50MHz，量程为100km时，使用的采样率是25MHz，量程为180km时，使用的采样率是12.5MHz，同时使用的光速值是299792458，而不是3×108。这样刷新数据包大小为 UploadLen*sizeof(Uint16) + 帧开销 = 2*UploadLen + 60 字节；最终数据包大小为 UploadLen*sizeof(Uint16) + 事件点开销 + 帧开销 = 2* UploadLen + 24*EventNum + 116 字节，其中EventNum是事件点数目，OTDR Module 可容纳的最大事件点数目是500。
 开发流程
上位机与OTDR模块建立连接后，按照第二章里的帧结构，使用命令0x10000000设置测试参数并发送到OTDR模块。如果OTDR模块检查到该命令参数合法，则会启动测试。由于OTDR模块采用主动上传数据的方式，上位机应随时准备接收数据以显示，并及时响应OTDR模块。OTDR模块上传的刷新数据不包含测试信息和事件点信息，只包含了曲线值，该数据包的大小对于一个量程来说是确定的。最终数据还要包含测试信息和事件点信息，所以数据包更大。
启动测试后，上位机在测试结束前不应该再使用命令0x10000000发送测试命令。如果违反了这一点，则可能引起测试错误，所以OTDR模块在测试过程中不再处理0x10000000命令。在测试过程中，如果上位机不想再继续往下测试，应该使用命令0x10000001取消或停止测试，然后才可以重新启动新的测试。当OTDR模块接收到取消测试命令后，如果数据采集已经完成，正在处理数据，则要等到数据处理完成才会继续响应上位机命令。
如果断开SOCKET连接，或者SOCKET传输出错，则OTDR模块会立即取消当前测试，并把所获得的数据全部丢弃。

// measurelength and pulsewidth
const int ml[3] = {60000, 100000, 180000};
const int pw[2][3] =
{
{80, 640, 1280},
{640, 5120, 5120},
};
// main function
int main(int argc, char *argv[])
{
char str[64];
int pulsewidth;
int i, count, sock, rxlen, curlen, totalrxlen, size;
struct sockaddr_in dst;
frame_header_t *header;
if(argc != 2)
{
printf(&quot;Usage : %s otdr_ip\n&quot;, argv[0]);
return 1;
}
size = sizeof(dst);
bzero(&dst, size);
dst.sin_family = PF_INET;
dst.sin_port = htons(5000);
dst.sin_addr.s_addr = inet_addr(argv[1]);// argv[1]是预连接的设备IP地址
sock = socket(PF_INET, SOCK_STREAM, 0);//定义socket对象
if(sock < 0)
{
perror(&quot;socket&quot;);
return -1;
}
printf(&quot;socket ok\n&quot;);
// set receive buffer size to 256K
count = 256*1024;
setsockopt(sock, SOL_SOCKET, SO_RCVBUF, &count, sizeof(count));//函数说明：setsockopt()用来设置参数s 所指定的socket 状态. 参数level 代表欲设置的网络层, 一般设成SOL_SOCKET 以存取socket 层. 参数optname 代表欲设置的选项。
if(connect(sock, (struct sockaddr*)&dst, size) < 0)
{
perror(&quot;connect&quot;);
printf(&quot;errno = %d\n&quot;, errno);
return -1;
}
printf(&quot;connect ok\n&quot;);
// start measure and receive data
for(i = 0; i < 3; i++)
{
for(pulsewidth = pw[0][i]; pulsewidth <= pw[1][i]; pulsewidth *= 2)
{
HostStartMeasure(sock, ml[i], pulsewidth);//开始测试
get_final = 0;
RETRY:
memset(str, 0, sizeof str);
snprintf(str, 64, &quot;d%dm_%dns.txt&quot;, ml[i], pulsewidth);
curlen = recv(sock, buf, sizeof(frame_header_t), 0);    // rcv frame header, get length info
if(curlen <= 0)
{
printf(&quot;%d : recv error --> %s\n&quot;, __LINE__, strerror(errno));
return -1;
}
// check for frame start string
if(strcmp(buf, FRAME_SYNC_STRING) != 0)
{
printf(&quot;frame sync string not found\n&quot;);
return -1;
}
// check for length
header = (frame_header_t*)buf;
totalrxlen = header->TotalLength;
totalrxlen -= sizeof(frame_header_t);
if(totalrxlen < 12)
{
printf(&quot;total rxlen error\n&quot;);
return -1;
}
// rcv remainder
rxlen = 0;
while(rxlen < totalrxlen)
{
curlen = recv(sock, buf+rxlen, totalrxlen-rxlen, 0);
if(curlen <= 0)
{
printf(&quot;%d : recv error --> %s\n&quot;, __LINE__, strerror(errno));
return -1;
}
rxlen += curlen;
}
rxlen = ProcessData(buf, rxlen, str);
NetworkIdle(sock);
if(get_final == 0)goto RETRY;
sleep(1);
}
}
printf(&quot;Measure Done\n&quot;);
close(sock);
return 0;
}
